================================================================================
                    API SPECIFICATION - ORGANIZATION REPORT FEATURE
                              (Báo cáo tổ chức)
================================================================================

Database Tables Used:
- reports (main table)
- organizations (for organization info)
- users (for reporter info)

Status Flow (theo DB): RECEIVED -> RESOLVED/REFUSED

Lưu ý:
- KHÔNG có tính năng lưu nháp (draft)
- User gửi báo cáo -> status = RECEIVED (chờ xử lý)
- Admin xử lý -> status = RESOLVED hoặc REFUSED

================================================================================

================================================================================
Get list of reports created by current user (filtered by target_type = 'ORGANIZATION')

Endpoint: GET /api/v1/reports/my-reports
Auth: Required (Bearer Token)

  - page (optional): number, default 0

================================================================================
                         STATUS MAPPING (DB -> UI)
================================================================================

Database Status  |  UI Label         |  Mô tả                    |  Can Edit?
-----------------|-------------------|---------------------------|------------
RECEIVED         |  Chờ xử lý        |  Báo cáo đang chờ Admin   |  NO
RESOLVED         |  Đã xử lý         |  Admin đã xử lý           |  NO
REFUSED          |  Từ chối          |  Admin từ chối, có thể sửa |  YES


================================================================================
                         ADMIN RESPONSE STRUCTURE
================================================================================

The adminResponse field needs to be stored. Options:
1. Add new table: report_responses (id, report_id, content, responded_at, responded_by)
2. Add columns to reports table: response_content, responded_at, responded_by

Recommended: Add columns to existing 'reports' table:

ALTER TABLE public.reports ADD COLUMN response_content text;
ALTER TABLE public.reports ADD COLUMN responded_at timestamp(6);
ALTER TABLE public.reports ADD COLUMN responded_by varchar(100);

OR create new table:

CREATE TABLE public.report_responses (
  id int8 GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  report_id int8 NOT NULL REFERENCES public.reports(id),
  content text NOT NULL,
  responded_at timestamp(6) NOT NULL DEFAULT NOW(),
  responded_by varchar(100) NOT NULL,
  CONSTRAINT uk_report_responses_report_id UNIQUE (report_id)
);


================================================================================
                         BUSINESS RULES
================================================================================

1. Users can only view/edit their own reports (where reporter_id = current_user.id)

2. Luồng báo cáo đơn giản:
   - User gửi báo cáo -> status = RECEIVED (chờ xử lý)
   - KHÔNG có tính năng lưu nháp
   - Admin duyệt hoặc từ chối

3. Reports can only be edited when:
   - status = REFUSED (bị từ chối, user có thể sửa và gửi lại)

4. When updating a REFUSED report:
   - Clear the adminResponse
   - Change status to RECEIVED (gửi lại để chờ xử lý)

5. Pagination: Use Spring Data JPA Pageable pattern

6. Always filter by target_type = 'ORGANIZATION' for this feature
